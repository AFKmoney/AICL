   149→def make_table(headers, rows, col_widths=None):
   150→    """Create a styled table."""
   151→    data = [headers] + rows
   152→    if col_widths is None:
   153→        n = len(headers)
   154→        col_widths = [CONTENT_W / n] * n
   155→    t = Table(data, colWidths=col_widths, repeatRows=1)
   156→    style_cmds = [
   157→        ('BACKGROUND', (0, 0), (-1, 0), TABLE_HEADER_COLOR),
   158→        ('TEXTCOLOR', (0, 0), (-1, 0), TABLE_HEADER_TEXT),
   159→        ('FONTNAME', (0, 0), (-1, 0), 'CarlitoBold'),
   160→        ('FONTSIZE', (0, 0), (-1, 0), 9.5),
   161→        ('FONTNAME', (0, 1), (-1, -1), 'Carlito'),
   162→        ('FONTSIZE', (0, 1), (-1, -1), 9),
   163→        ('LEADING', (0, 0), (-1, -1), 13),
   164→        ('ALIGN', (0, 0), (-1, -1), 'LEFT'),
   165→        ('VALIGN', (0, 0), (-1, -1), 'TOP'),
   166→        ('TOPPADDING', (0, 0), (-1, -1), 4),
   167→        ('BOTTOMPADDING', (0, 0), (-1, -1), 4),
   168→        ('LEFTPADDING', (0, 0), (-1, -1), 6),
   169→        ('RIGHTPADDING', (0, 0), (-1, -1), 6),
   170→        ('GRID', (0, 0), (-1, -1), 0.4, colors.HexColor('#cccccc')),
   171→    ]
   172→    for i in range(1, len(data)):

   905→    story.append(p(
   906→        "A critical area for future development is memory management. The goal is to provide an "
   907→        "ultra-simple ownership model that is more effective than existing systems like Zig's "
   908→        "manual memory management. The challenge is to express ownership and lifetime semantics "
   909→        "within AICL's architectural specification paradigm, where the programmer describes intent "
   910→        "rather than implementation. A promising direction is to derive ownership rules from the "
   911→        "Layer and Entity structure: layers own their entities, behaviors borrow entities from their "
   912→        "layers, and the compiler enforces borrow checking at the architectural level before "

   944→        "where the generated code includes monitoring hooks that detect risk conditions and "
   945→        "trigger the corresponding recovery code. The provenance system would extend to "

   966→        "than treating architecture as documentation that informs code, AICL treats architecture "

   968→        "automatic test generation, and full compilation provenance."

   970→    story.append(p(
   971→        "The central contribution of this work is the principle of explicable compilation: the "

   974→        "implemented through a provenance system that records every compilation decision, a "
   975→        "deterministic compilation contract that makes provenance reproducible, and a language "

   982→        "the memory management system needs to be designed and implemented. But the core "
   983→        "idea—that compilers should be able to explain themselves, and that this explainability "
   984→        "should be enforced by design rather than added as an afterthought—is one that deserves "
   985→        "serious exploration."
   986→    ))

   991→        "principle of explicable compilation offers a different direction. Not more code generation, "
   992→        "but more accountable code generation. Not faster compilation, but more transparent "
   993→        "compilation. Not AI that writes code, but compilers that can explain the code they write."
